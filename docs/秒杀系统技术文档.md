# 校园生活平台 - 秒杀系统技术文档

## 📋 项目概述

### 业务场景
校园生活平台的优惠券秒杀功能，用于发放限量特价优惠券。用户需要在规定时间内抢购，系统需要保证：
- **高性能**：支持高并发场景，快速响应用户请求
- **高可用**：系统稳定运行，零异常
- **数据一致性**：绝不超卖，库存扣减准确

### 核心挑战
| 挑战 | 说明 |
|------|------|
| **高并发** | 1000+ 用户同时抢购 100 张券 |
| **超卖问题** | 库存扣减的原子性保证 |
| **重复购买** | 同一用户只能购买一次 |
| **性能瓶颈** | 数据库成为系统瓶颈 |

## 🔧 核心实现

### 1. 秒杀流程（同步部分）

```java
public Long seckillVoucher(Long voucherId) {
    // 1. 获取当前用户
    Long userId = UserHolder.getUser();
    
    // 2. 从 Redis 查询优惠券信息（预热数据）
    Voucher voucher = stringRedisTemplate.opsForHash()
        .entries("seckill:info:" + voucherId, Voucher.class);
    
    // 3. 校验优惠券状态、时间
    if (!checkVoucherValid(voucher)) {
        throw new BusinessException("优惠券不可用");
    }
    
    // 4. 执行 Lua 脚本（原子操作）
    DefaultRedisScript<Long> script = new DefaultRedisScript<>();
    script.setScriptText(SECKILL_SCRIPT);
    script.setResultType(Long.class);
    
    Long result = stringRedisTemplate.execute(
        script,
        List.of(
            "seckill:stock:" + voucherId,
            "seckill:order:" + voucherId
        ),
        voucherId.toString(),
        userId.toString()
    );
    
    // 5. 判断结果
    if (result != 0) {
        // 1: 库存不足  2: 重复购买
        throw new BusinessException(getErrorMsg(result));
    }
    
    // 6. 返回成功（异步处理订单）
    return null; // 表示"抢购成功，正在排队"
}
```

### 2. Lua 脚本（原子操作）

```lua
-- KEYS[1]: 库存 key (seckill:stock:{id})
-- KEYS[2]: 订单 key (seckill:order:{id})
-- ARGV[1]: 优惠券ID
-- ARGV[2]: 用户ID

-- 1. 获取库存
local stock = tonumber(redis.call('get', KEYS[1]))
if (stock <= 0) then
    return 1  -- 库存不足
end

-- 2. 判断用户是否已购买
if (redis.call('sismember', KEYS[2], ARGV[2]) == 1) then
    return 2  -- 重复购买
end

-- 3. 扣减库存
redis.call('incrby', KEYS[1], -1)

-- 4. 记录用户
redis.call('sadd', KEYS[2], ARGV[2])

-- 5. 发送消息到 Stream
redis.call('xadd', 'stream:voucher:order', '*', 
    'voucherId', ARGV[1], 'userId', ARGV[2])

return 0  -- 成功
```

### 3. 异步订单处理（Stream 消费者）

```java
@PostConstruct
public void init() {
    // 创建 Stream 消费组
    stringRedisTemplate.opsForStream().createGroup(
        "stream:voucher:order", 
        "seckill-group"
    );
    
    // 启动消费线程
    executorService = Executors.newSingleThreadExecutor();
    executorService.submit(() -> {
        while (true) {
            try {
                // 从 Stream 读取消息
                List<MapRecord<String, Object, Object>> records = 
                    stringRedisTemplate.opsForStream().read(
                        Consumer.from("seckill-group", "consumer-1"),
                        StreamReadOptions.empty().count(1).block(Duration.ofSeconds(2)),
                        StreamOffset.create("stream:voucher:order", ReadOffset.lastConsumed())
                    );
                
                if (records == null || records.isEmpty()) continue;
                
                // 处理订单
                handleVoucherOrder(records.get(0));
            } catch (Exception e) {
                log.error("处理秒杀订单失败", e);
            }
        }
    });
}

private void handleVoucherOrder(MapRecord<String, Object, Object> record) {
    Map<Object, Object> value = record.getValue();
    Long voucherId = Long.valueOf(value.get("voucherId").toString());
    Long userId = Long.valueOf(value.get("userId").toString());
    
    // 获取分布式锁
    RLock lock = redissonClient.getLock("lock:voucher:order:" + userId);
    try {
        if (lock.tryLock(5, 10, TimeUnit.SECONDS)) {
            createVoucherOrder(userId, voucherId);
            // ACK 消息
            stringRedisTemplate.opsForStream().acknowledge(
                "stream:voucher:order", 
                "seckill-group", 
                record.getId()
            );
        }
    } catch (InterruptedException e) {
        log.error("获取分布式锁失败", e);
    } finally {
        if (lock.isHeldByCurrentThread()) {
            lock.unlock();
        }
    }
}

private void createVoucherOrder(Long userId, Long voucherId) {
    // 1. 检查是否重复下单（数据库唯一索引）
    LambdaQueryWrapper<Order> wrapper = new LambdaQueryWrapper<>();
    wrapper.eq(Order::getUserId, userId)
           .eq(Order::getVoucherId, voucherId);
    if (orderService.count(wrapper) > 0) {
        log.warn("用户已购买该优惠券");
        return;
    }
    
    // 2. 扣减库存（乐观锁）
    boolean success = seckillVoucherService.update()
        .setSql("stock = stock - 1")
        .eq("voucher_id", voucherId)
        .gt("stock", 0)
        .update();
    
    if (!success) {
        throw new BusinessException("库存不足");
    }
    
    // 3. 创建订单
    Order order = new Order();
    order.setUserId(userId);
    order.setVoucherId(voucherId);
    order.setStatus(1); // 待支付
    orderService.save(order);
}
```

## 🛡️ 三层防超卖机制

### 为什么需要三层防护？

```
场景：Stream 消息处理失败，进入 pending list，被重试
风险：同一条消息可能被处理多次，导致超卖
```

### 三层防护详解

| 层级 | 机制 | 位置 | 作用 |
|------|------|------|------|
| **第一层** | Redis Lua 原子操作 | VoucherService | 快速拦截重复请求，O(1) 时间复杂度 |
| **第二层** | Redisson 分布式锁 | VoucherOrderHandler | 防止 Stream 重试导致并发处理 |
| **第三层** | 数据库唯一索引 | createVoucherOrder | 最终兜底，即使并发也能保证唯一性 |

### 第一层：Redis Lua 原子操作

**原理**：Lua 脚本在 Redis 中是原子执行的，不会被其他命令打断。

**代码**：
```lua
-- 检查库存
local stock = tonumber(redis.call('get', KEYS[1]))
if (stock <= 0) then return 1 end

-- 检查重复
if (redis.call('sismember', KEYS[2], ARGV[2]) == 1) then return 2 end

-- 扣减库存 + 记录用户（原子操作）
redis.call('incrby', KEYS[1], -1)
redis.call('sadd', KEYS[2], ARGV[2])
```

**优势**：
- ✅ 高性能：所有操作在 Redis 中完成，无需网络往返
- ✅ 原子性：Lua 脚本执行期间不会被中断
- ✅ 快速失败：库存不足或重复购买立即返回

### 第二层：Redisson 分布式锁

**原理**：使用 Redisson 的分布式锁，确保同一条消息不会被并发处理。

**代码**：
```java
// 锁的 key: lock:voucher:order:{userId}
RLock lock = redissonClient.getLock("lock:voucher:order:" + userId);
try {
    // 尝试获取锁，最多等待 5 秒，锁自动释放时间 10 秒
    if (lock.tryLock(5, 10, TimeUnit.SECONDS)) {
        createVoucherOrder(userId, voucherId);
    }
} finally {
    if (lock.isHeldByCurrentThread()) {
        lock.unlock();
    }
}
```

**优势**：
- ✅ 防止并发：同一条消息只能被一个线程处理
- ✅ 自动释放：锁超时自动释放，防止死锁
- ✅ 可重入：同一线程可以重复获取锁

### 第三层：数据库唯一索引

**原理**：在订单表上创建 `(user_id, voucher_id)` 联合唯一索引。

**代码**：
```java
// 创建订单前检查
LambdaQueryWrapper<Order> wrapper = new LambdaQueryWrapper<>();
wrapper.eq(Order::getUserId, userId)
       .eq(Order::getVoucherId, voucherId);
if (orderService.count(wrapper) > 0) {
    return; // 已购买，直接返回
}

// 创建订单
orderService.save(order);
```

**优势**：
- ✅ 最终兜底：即使并发也能保证唯一性
- ✅ 数据一致性：数据库层面的强约束
- ✅ 可审计：所有订单都有记录

## 🚀 性能优化

### 1. 预热机制

**问题**：每次秒杀都要查询数据库，性能瓶颈。

**解决方案**：应用启动时预热数据到 Redis。

```java
@PostConstruct
public void init() {
    // 1. 查询所有秒杀券
    List<SeckillVoucher> vouchers = seckillVoucherService.list();
    
    // 2. 预热库存
    vouchers.forEach(voucher -> {
        stringRedisTemplate.opsForValue()
            .set("seckill:stock:" + voucher.getId(), 
                 voucher.getStock().toString());
    });
    
    // 3. 预热优惠券信息
    vouchers.forEach(voucher -> {
        stringRedisTemplate.opsForHash()
            .putAll("seckill:info:" + voucher.getId(), 
                    BeanUtil.beanToMap(voucher));
    });
    
    log.info("✅ 秒杀券预热完成，共 {} 个", vouchers.size());
}
```

**效果**：
- ✅ 秒杀时直接查询 Redis，无需访问数据库
- ✅ 响应时间从 100ms+ 降低到 10ms 以内

### 2. 连接池优化

**问题**：默认连接池太小（10 个连接），高并发时成为瓶颈。

**解决方案**：增加连接池大小。

```yaml
spring:
  data:
    redis:
      lettuce:
        pool:
          max-active: 100   # 最大连接数（原 10）
          max-idle: 50      # 最大空闲连接
          min-idle: 20      # 最小空闲连接
```

**效果**：
- ✅ 支持 100 个并发 Redis 操作
- ✅ 减少连接等待时间

### 3. Lua 脚本原子操作

**问题**：多个 Redis 命令之间可能被其他请求打断。

**解决方案**：使用 Lua 脚本保证原子性。

**效果**：
- ✅ 库存检查和扣减是原子操作
- ✅ 避免竞态条件

## 🔍 优化历程

### 问题 1：Token 过期导致全部 401

**现象**：所有请求返回 401 Unauthorized。

**原因**：测试 Token 有效期 24 小时，压测时已过期。

**解决**：
```yaml
jwt:
  expiration: 604800000  # 7 天（原 24 小时）
```

### 问题 2：库存为 0 导致全部失败

**现象**：所有请求返回"库存不足"。

**原因**：之前测试已经扣完库存，没有重置。

**解决**：
```bash
# 重置 Redis 库存
SET seckill:stock:1001 100

# 重置数据库库存
UPDATE seckill_voucher SET stock = 100 WHERE voucher_id = 1001
```

### 问题 3：超卖（订单数 > 库存数）

**现象**：库存 100，但创建了 148 个订单。

**原因**：Stream 消息处理失败后重试，同一条消息被处理多次。

**解决**：添加三层防超卖机制（Lua + 分布式锁 + 唯一索引）。

### 问题 4：Stream 消费组不存在

**现象**：启动时抛出 `NOGROUP` 错误。

**原因**：清理测试数据时删除了 Stream 和消费组。

**解决**：
```java
@PostConstruct
public void init() {
    // 自动创建 Stream
    if (!stringRedisTemplate.hasKey("stream:voucher:order")) {
        stringRedisTemplate.opsForStream().add(
            "stream:voucher:order", 
            Map.of("placeholder", "1")
        );
    }
    
    // 自动创建消费组
    try {
        stringRedisTemplate.opsForStream().createGroup(
            "stream:voucher:order", 
            "seckill-group"
        );
    } catch (Exception e) {
        // 已存在，忽略
    }
}
```

## 🎯 面试常见问题

### Q1: 为什么选择 Redis Stream 而不是 RabbitMQ？

**回答**：
1. **轻量级**：Redis 已经用于缓存，不需要额外引入消息队列
2. **高性能**：Redis 的内存操作比 RabbitMQ 更快
3. **功能足够**：Stream 支持消费组、ACK、持久化，满足秒杀场景需求
4. **运维成本低**：不需要额外部署和维护 RabbitMQ

### Q2: 如何保证不超卖？

**回答**：
采用三层防护机制：
1. **第一层**：Redis Lua 脚本原子操作，快速拦截重复请求
2. **第二层**：Redisson 分布式锁，防止 Stream 重试导致并发处理
3. **第三层**：数据库唯一索引，最终兜底保证唯一性

### Q3: 如果 Redis 宕机了怎么办？

**回答**：
1. **高可用部署**：生产环境使用 Redis Sentinel 或 Redis Cluster
2. **降级策略**：Redis 不可用时，降级到数据库层面处理（性能下降但可用）
3. **熔断机制**：使用 Sentinel 熔断秒杀功能，返回"系统繁忙"

### Q4: 为什么使用异步处理？

**回答**：
1. **削峰填谷**：将瞬时高并发请求分散到后续时间处理
2. **快速响应**：用户立即得到"抢购成功"的反馈，无需等待订单创建
3. **提高吞吐量**：数据库可以按自己的处理能力消费消息

### Q5: 如何处理恶意请求？

**回答**：
1. **限流**：使用令牌桶或滑动窗口限流，限制单用户请求频率
2. **验证码**：秒杀前要求输入验证码，防止脚本刷单
3. **黑名单**：对异常用户加入黑名单，禁止参与秒杀
4. **IP 限制**：限制同一 IP 的请求频率

### Q6: 库存预热策略是什么？

**回答**：
1. **启动时预热**：应用启动时加载所有秒杀券的库存和信息到 Redis
2. **定时刷新**：定时任务定期刷新库存，保证数据一致性
3. **活动前预热**：活动开始前 10 分钟，使用定时任务预热

### Q7: 如何监控秒杀系统？

**回答**：
1. **业务指标**：QPS、响应时间、成功率、库存消耗速度
2. **系统指标**：CPU、内存、网络、磁盘 IO
3. **工具**：Prometheus + Grafana 监控，ELK 日志分析
4. **告警**：设置阈值告警，及时发现问题

### 完整的 VoucherOrderHandler

```java
@Component
@Slf4j
public class VoucherOrderHandler {
    
    @Autowired
    private StringRedisTemplate stringRedisTemplate;
    
    @Autowired
    private RedissonClient redissonClient;
    
    @Autowired
    private SeckillVoucherService seckillVoucherService;
    
    @Autowired
    private VoucherOrderService orderService;
    
    private ExecutorService executorService;
    
    @PostConstruct
    public void init() {
        // 创建 Stream
        if (!Boolean.TRUE.equals(stringRedisTemplate.hasKey("stream:voucher:order"))) {
            stringRedisTemplate.opsForStream().add(
                "stream:voucher:order", 
                Map.of("placeholder", "1")
            );
        }
        
        // 创建消费组
        try {
            stringRedisTemplate.opsForStream().createGroup(
                "stream:voucher:order", 
                "seckill-group"
            );
        } catch (Exception e) {
            log.debug("消费组已存在");
        }
        
        // 启动消费线程
        executorService = Executors.newSingleThreadExecutor();
        executorService.submit(this::handlePendingList);
        executorService.submit(this::handleFailedMessages);
        
        log.info("✅ 秒杀订单处理器启动完成");
    }
    
    private void handlePendingList() {
        while (true) {
            try {
                List<MapRecord<String, Object, Object>> records = 
                    stringRedisTemplate.opsForStream().read(
                        Consumer.from("seckill-group", "consumer-1"),
                        StreamReadOptions.empty().count(1).block(Duration.ofSeconds(2)),
                        StreamOffset.create("stream:voucher:order", ReadOffset.lastConsumed())
                    );
                
                if (records == null || records.isEmpty()) continue;
                
                handleVoucherOrder(records.get(0));
            } catch (Exception e) {
                log.error("处理秒杀订单失败", e);
            }
        }
    }
    
    private void handleFailedMessages() {
        while (true) {
            try {
                List<MapRecord<String, Object, Object>> records = 
                    stringRedisTemplate.opsForStream().read(
                        Consumer.from("seckill-group", "consumer-1"),
                        StreamReadOptions.empty().count(1),
                        StreamOffset.create("stream:voucher:order", ReadOffset.from("0"))
                    );
                
                if (records == null || records.isEmpty()) {
                    Thread.sleep(2000);
                    continue;
                }
                
                handleVoucherOrder(records.get(0));
            } catch (Exception e) {
                log.error("处理失败消息异常", e);
            }
        }
    }
    
    private void handleVoucherOrder(MapRecord<String, Object, Object> record) {
        Map<Object, Object> value = record.getValue();
        Long voucherId = Long.valueOf(value.get("voucherId").toString());
        Long userId = Long.valueOf(value.get("userId").toString());
        
        RLock lock = redissonClient.getLock("lock:voucher:order:" + userId);
        try {
            if (lock.tryLock(5, 10, TimeUnit.SECONDS)) {
                createVoucherOrder(userId, voucherId);
                stringRedisTemplate.opsForStream().acknowledge(
                    "stream:voucher:order", 
                    "seckill-group", 
                    record.getId()
                );
            }
        } catch (InterruptedException e) {
            log.error("获取分布式锁失败", e);
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }
    
    private void createVoucherOrder(Long userId, Long voucherId) {
        // 1. 检查是否重复下单
        LambdaQueryWrapper<Order> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(Order::getUserId, userId)
               .eq(Order::getVoucherId, voucherId);
        if (orderService.count(wrapper) > 0) {
            log.warn("用户已购买该优惠券");
            return;
        }
        
        // 2. 扣减库存
        boolean success = seckillVoucherService.update()
            .setSql("stock = stock - 1")
            .eq("voucher_id", voucherId)
            .gt("stock", 0)
            .update();
        
        if (!success) {
            throw new BusinessException("库存不足");
        }
        
        // 3. 创建订单
        Order order = new Order();
        order.setUserId(userId);
        order.setVoucherId(voucherId);
        order.setStatus(1);
        orderService.save(order);
    }
}
```
